# Risk register

Live register for the portfolio program. Small and honest by design: a risk appears here
because it is real, has an owner (me), and has a mitigation someone can audit. Reviewed
quarterly per the [operating model](operating-model.md).

Scoring rubric: likelihood over the next four quarters, High above 50%, Medium 10 to 50%,
Low under 10%. Impact High means a core portfolio claim breaks in public. Scored by the
owner at quarterly review.

| ID | Risk | Likelihood | Impact | Mitigation | Status |
| --- | --- | --- | --- | --- | --- |
| R1 | Solo maintainer: the portfolio goes stale during work crunches | High | High | Weekly cadence capped at 45 minutes so it survives busy weeks; quarterly note is the floor; bit-rot canary CI (planned, flightdeck milestone) opens issues when quickstarts break | Open |
| R2 | Self-merged PRs read as undisciplined | Medium | Medium | Live: branch protection binding the administrator on this repo and every pinned repo (required checks `ci` and `gitleaks`, zero approvals because GitHub forbids self-approval); published review policy ([decision 0002](decisions/0002-solo-maintainer-review-policy.md)); twoseat reviews every code pull request in advisory mode at v0.1.0; flightdeck publishes the gate-bypass rate nightly and lists unlabeled bypasses by link. Not mitigated and stated in public: no second human reviews a merge ([decision 0006](decisions/0006-ai-authored-code-human-owned-decisions.md)) | Mitigated to the solo-scale floor; residual accepted |
| R3 | Sanitization failure links public content to private work | Low | High | Disclosure policy ([decision 0003](decisions/0003-sanitization-and-disclosure-policy.md)); a secret-scanning gate in CI (live in this repo, shipping with field-notes' first PR, extending to each flagship before its first code PR); second-model review on field-notes before publish; owner verification at review | Mitigated, residual accepted |
| R4 | Model API pricing or behavior change breaks twoseat budgets and benchmark validity | Medium | Medium | Live in twoseat v0.1.0: a `cost-ceiling-usd` input checked before the seat is called, degrading the run to `not-reviewed` rather than failing it; token rates are workflow inputs dated in the workflow file, never a price table inside the action; scores compare only within one prompt version, pinned by a fingerprint test. Residual: synthetic scores are an upper bound, and a model or prompt change invalidates them. A re-run costs about $0.41 (the recorded run's total at the dated rates, from `bench/results/scorecard.json`) and needs explicit approval each time | Mitigated, residual accepted |
| R5 | Org-style handle confuses reviewers looking for a person | Low | Low | Profile README leads with the person; accepted per [decision 0001](decisions/0001-portfolio-scope-account-and-pins.md); revisit on evidence it costs an opportunity | Accepted |
| R6 | GitHub disables a scheduled workflow after 60 days without repository activity, so flightdeck's nightly run goes silent and the profile card goes stale | Medium | High | The card prints its generation date, so staleness declares itself on the profile; the reliability tile shows the last 30 nights from the workflow's own run list; flightdeck's runbook carries the re-enable command. No keepalive commits: a commit made to keep a schedule alive is activity theater, and the cure is visibility | Open, mitigated by visibility |
| R7 | Small denominators turn rates into noise: a 90-day window over a solo portfolio yields single-digit event counts, and a percentage over five events reads as precision it does not have | High | Medium | Any rate under 10 events renders as a count ("n of m"), never a percentage; any empty set renders as "not measured", never 0 or NaN; both rules live in one flightdeck module (`src/format.ts`) with tests, so no tile can bypass them | Mitigated |
